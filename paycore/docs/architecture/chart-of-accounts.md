# План счетов (Chart of Accounts)

Статус: **проект**. Правила дебета и кредита — в [ledger-model.md §5](ledger-model.md#5-правила-дебета-и-кредита). Использование счетов в сценариях — в [money-flows.md](money-flows.md).

## 1. Принципы

- План счетов задаёт **типы** ledger-счетов (`account_type` = код CoA). Конкретный ledger-счёт — это тип, владелец и валюта.
- **Пользовательские счета** (2100/2110, 2200/2210) создаются автоматически при открытии бизнес-счёта: пара «доступно + резерв» в валюте счёта.
- **Системные счета** создаются сидом (seed-миграцией) на каждую поддерживаемую валюту: `<код>:<валюта>`, например `4200:RUB`. Владелец — `SYSTEM`.
- Нумерация оставляет промежутки для расширения. Коды условные и не соответствуют российскому плану счетов (ПБУ/ЦБ) — это демонстрационная модель.
- Каждый тип имеет признаки: класс, нормальное сальдо, допустимость отрицательного остатка, наличие синхронной проекции.

## 3. Отображение на таблицы

| Сущность | `ledger_accounts.owner_type` | `account_id` | `account_type` | `kind` |
|---|---|---|---|---|
| Счёт клиента «Основной RUB» | CUSTOMER | id бизнес-счёта | 2100 и 2110 | AVAILABLE / HOLD |
| Счёт мерчанта (RUB) | MERCHANT | id бизнес-счёта мерчанта | 2200 и 2210 | AVAILABLE / HOLD |
| Доход от платежей, RUB | SYSTEM | NULL | 4200 | — |

- Уникальность: `UNIQUE (account_id, kind)` для пользовательских счетов. Для системных — `UNIQUE (account_type, currency) WHERE owner_type = 'SYSTEM'`.
- Системный код для поиска из кода приложения: `system_code` вида `FEE_INCOME_PAYMENTS`, `SETTLEMENT_BANK`, `PROVIDER_RECEIVABLE`. Приложение ищет счёт по `(system_code, currency)`, а не по UUID.
- Мерчант получает по одному бизнес-счёту на каждую валюту приёма платежей ([Q-07](open-questions.md#q-07)). Есть ли у мерчанта несколько счетов (по магазинам) — тоже открытый вопрос.

## 4. Проверка «баланса баланса»

По каждой валюте в любой момент:

\[
\sum_{1xxx} + \sum_{5xxx} = \sum_{2xxx} + \sum_{3xxx} + \sum_{4xxx}
\]

(с учётом контр-счёта 4900). Это эквивалентно инварианту I-02 (\(\sum D = \sum C\) по всем проводкам). Пробный баланс (trial balance) — один из отчётов Admin Dashboard / Ledger Explorer.

## 5. Пример: состояние после демо-сценария

Клиент пополнил счёт на 10 000 ₽, оплатил покупку у мерчанта на 5 000 ₽ (комиссия 75 ₽), получил частичный возврат 2 000 ₽. Комиссия не возвращается (D-09, вариант A).

| Счёт | Дебет, коп. | Кредит, коп. | Сальдо |
|---|---|---|---|
| 1100 Банк | 1 000 000 | 0 | Дт 1 000 000 |
| 2100 Клиент доступно | 500 000 (hold) | 1 000 000 (topup) + 200 000 (refund) | Кт 700 000 |
| 2110 Клиент резерв | 500 000 (capture) | 500 000 (hold) | 0 |
| 2200 Мерчант доступно | 200 000 (refund) | 492 500 (capture) | Кт 292 500 |
| 4200 Доход платежи | 0 | 7 500 | Кт 7 500 |
| **Итого** | **2 200 000** | **2 200 000** | Дт 1 000 000 = Кт 700 000 + 292 500 + 7 500 |

Подробные проводки по шагам — в [money-flows.md](money-flows.md).

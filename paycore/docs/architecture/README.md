## Ключевые решения (кратко)

1. **Ledger — первоисточник.** Журнал из ≥ 2 проводок, в каждой валюте \(\sum D = \sum C\), записи append-only, исправления — только сторно и корректировки (maker-checker).
2. **Деньги — `BIGINT` в минорных единицах**, справочник валют с `minor_units`, арифметика с проверкой переполнения, округление только в Commission Engine (`HALF_UP`, ставки в bp).
3. **Бизнес-счёт ↔ два ledger-счёта** (доступно 2100/2200 и резерв 2110/2210). Деньги клиентов и мерчантов — обязательства (кредитовое сальдо).
4. **Резерв — это проводка** (Дт «доступно» / Кт «резерв»), поэтому `reserved_amount` восстанавливается из ledger.
5. **Проекция `account_balances` только у пользовательских счетов**, обновляется в той же транзакции и служит строкой блокировки. Системные счета без проекции, чтобы не было горячих строк.
6. **Защита от двойного списания:** READ COMMITTED + `FOR UPDATE` в едином порядке блокировок + `CHECK (available_amount >= 0)` + `UNIQUE (ledger_account_id, account_version)`.
7. **Идемпотентность в два уровня:** HTTP-ключ в той же транзакции и бизнес-`UNIQUE (reference_type, reference_id, operation)` в ledger.
8. **Outbox в той же транзакции, inbox у потребителей;** внутри транзакций нет внешних вызовов. Retry всей транзакции на `40001`/`40P01`.
9. **Целостность в БД:** составные FK по валюте, отложенный триггер баланса журнала, триггеры и права против UPDATE/DELETE.
